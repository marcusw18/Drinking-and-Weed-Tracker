# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

iOS + Apple Watch harm-reduction app that tracks alcohol intake, estimates BAC in real-time using the Widmark formula, and runs AI-powered intoxication analysis combining voice (Whisper slur detection), face (Vision redness), and Apple Watch health data.

## Commands

### Generate & Open Xcode Project
```bash
xcodegen generate
open DrinkingTracker.xcodeproj
```
Must be re-run after modifying `project.yml` (adding files, changing targets, updating packages).

### Vulture ML Server
```bash
cd vulture-server
source venv/bin/activate
python main.py                    # starts on :8000, hot-reloads with --reload
uvicorn main:app --reload         # alternative
```

Test the voice endpoint manually:
```bash
curl -X POST http://localhost:8000/analyze/voice \
  -F "audio=@test.m4a"
```

### Python dependencies
```bash
cd vulture-server
pip install -r requirements.txt   # includes openai-whisper (~74MB model download on first run)
```

## Architecture

### State Management
`AppState` (`DrinkingTracker/App/AppState.swift`) is the single source of truth, marked `@Observable` (iOS 17 macro). It is injected at the root via `.environment(appState)` and consumed with `@Environment(AppState.self)` in every view. It holds: Firebase user, current BAC/stage, drink logs, analysis logs, health metrics, and all sheet-presentation booleans.

### Data Flow
1. User adds a drink → `DrinkLogViewModel` saves to Supabase → inserts into `appState.drinkLogs` → calls `appState.refreshBAC()` which recomputes via `BACCalculator.currentBAC(drinks:profile:)`
2. Auto-analysis fires every 15 min via `AutoAnalysisTimer` (wraps `Timer`) while session is active
3. Manual analysis: `AnalysisViewModel` orchestrates the full pipeline — requests Watch data (WatchConnectivity), captures face photo (UIImagePickerController/Vision), POSTs audio to Vulture server, calls Gemini for summary, saves `AnalysisLog` to Supabase

### Services (all singletons via `.shared`)
- `SupabaseService` — wraps `supabase-swift` v2; all queries use `async/await` and `.execute().value` decoding
- `GeminiService` — wraps `GoogleGenerativeAI`; `stageSummary()` for one-shot analysis, `startChat()`/`sendChatMessage()` for the chatbot
- `VultureService` — multipart POST to the FastAPI server; returns `VultureResponse` with `transcript` + `slurScore`
- `HealthKitService` — reads last-hour samples for HR, HRV, SpO2; call `refreshAll()` before analysis
- `WatchSessionManager` (iOS) — sends `"startCapture"` message to watch, receives health dict via `sendMessage` and audio file via `transferFile`

### iPhone ↔ Watch Communication
- `WatchSessionManager` (iOS, `DrinkingTracker/Services/`) sends requests and receives responses
- `WatchSessionManagerWatch` (watchOS, `WatchApp/WatchSessionManager.swift`) records 60s audio + reads HealthKit, then sends health dict via `sendMessage` and audio via `transferFile`
- Stage/BAC sync to watch is done via `updateApplicationContext`

### Vulture Server
FastAPI app at `vulture-server/main.py`. Two-step pipeline in `routes/voice.py`:
1. `whisper_model.py` — loads `openai-whisper` base model (lazy singleton), returns transcript
2. `slur_detector.py` — scores transcript on 4 heuristics (repetition, fillers, phonetic slur pairs, sentence coherence); weighted sum → 0.0–1.0

### Database (Supabase)
Three tables: `user_profiles`, `drink_logs`, `analysis_logs`. Schema in `supabase/migrations/001_initial.sql`. All models use snake_case `CodingKeys` to match column names. Firebase UID is the `user_id` foreign key. RLS is enabled but permissive (service-role key used on client for hackathon; tighten via Supabase custom JWT + Firebase JWKS for production).

## Configuration

All external credentials live in `DrinkingTracker/Config.swift`. This file must be filled in before building — the app will crash on launch if Supabase URL is invalid. The Vulture server URL must be the machine's LAN IP (not `localhost`) when running on a physical device.

`GoogleService-Info.plist` (from Firebase Console) must be manually added to the `DrinkingTracker` Xcode target — it is gitignored and not generated by XcodeGen.

## Key Constraints

- **Physical device required**: HealthKit, WatchConnectivity, and camera do not work in the Simulator
- **Whisper model download**: First call to `transcribe_audio()` downloads ~74 MB; expect a slow first request
- **`@Observable` requires iOS 17+**: Do not use `ObservableObject`/`@Published` in the iPhone app; use `@Observable` and `@Bindable` instead
- **WatchApp uses `ObservableObject`**: `WatchSessionManagerWatch` uses `@Published` because it's a `watchOS` target where `@Observable` support may vary; keep this consistent
